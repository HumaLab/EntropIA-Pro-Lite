# Fix blank OCR PDF exports

Keep the existing `html2pdf.js` adapter, but move off-screen positioning from the element supplied to `html2pdf` onto a staging wrapper. The export target then retains normal layout when cloned, so generated PDFs contain the prepared OCR text and images.

## Verified failure

- The reported PDF is one blank page and 3,058 bytes.
- Calling the current `generateOcrExportBytes('pdf', ...)` path in Chromium with visible text also produces a blank 3,058-byte PDF.
- `generatePdfBytes` applies `position: fixed` and `inset-inline-start: -100000px` directly to the element passed to `.from(...)`.
- `html2pdf.js` clones the supplied element, including those inline styles, so the cloned content remains outside the captured page.
- In the control experiment, an off-screen wrapper containing an unpositioned 180 mm-wide export target produced a 408,272-byte PDF with visible text.

## Implementation

In `apps/desktop/src/lib/ocr-export.ts`:

1. Create a fixed staging wrapper positioned far outside the application viewport.
2. Create a child export target with the existing 180 mm width and prepared HTML.
3. Append the target to the wrapper and the wrapper to `document.body`.
4. Pass the child export target—not the wrapper—to `html2pdf().from(...)`.
5. Remove the wrapper in `finally` after success or failure.

The public export API, prepared HTML, PDF options, Markdown adapter, DOCX adapter, save dialog, filenames, and OCR-region resolution remain unchanged.

## Error handling

The existing `try/finally` contract remains authoritative. Any dynamic-import, rendering, or PDF-output failure removes the complete staging subtree and propagates to the existing UI error state. No partial file is written because byte generation still completes before `writeFile` runs.

## Verification

### Regression test

Extend `apps/desktop/src/lib/ocr-export.test.ts` before changing production code. The mocked `html2pdf` chain must capture the element passed to `.from(...)` and prove:

- the export target itself is not fixed or displaced off-screen;
- its parent is the off-screen staging wrapper while generation is active;
- the staging wrapper is removed after generation;
- the generated bytes still flow through the existing adapter contract.

The test must fail against the current implementation, then pass after the repair.

### Behavioral smoke check

Run the real Vite module in Chromium and generate a PDF from visible OCR text through `generateOcrExportBytes('pdf', ...)`. Open the returned bytes in Chromium and confirm the text is visible on page 1. This exercises the actual `html2pdf.js`, `html2canvas`, and jsPDF path that the unit mock cannot render.

### Focused checks

- `VITE_LOCAL_ML=0 pnpm --filter @entropia-pro/desktop test -- src/lib/ocr-export.test.ts`
- `VITE_LOCAL_ML=0 pnpm --filter @entropia-pro/desktop typecheck`

## Non-goals

- Replacing `html2pdf.js` or changing PDF visual styling.
- Adding pagination controls, print settings, or alternate PDF engines.
- Changing Markdown, DOCX, OCR parsing, crop resolution, or persistence behavior.
